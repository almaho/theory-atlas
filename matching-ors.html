What is executed, and what is illustrated?

Dynamic graph: Algorithm 2’s edge updates, counters, refresh schedule, phase reset, and certificate bookkeeping are executed. The example uses n = 16, ε = ½, and a teaching threshold t = 16. MatchAndCertify’s input/output contract is illustrated using an exact solver on this small graph; this is not an implementation or timing demonstration of the full boosting algorithm.

Sampling: the sampling loop uses a seeded random generator, n = 16 and δ = ¼. Samples are uniform subsets without replacement, capped at the remaining set size; the paper does not specify replacement. Every replay keeps the seed, while “New random run” changes it. The displayed run ends at the printed loop limit if no round succeeds. The v4 pseudocode’s loop limit and its proof’s final-budget discussion differ; this page does not silently extend the loop.

Certificates: Hcert can contain stale edges and need not be a matching. Deleted edges are filtered out before a refresh. A certificate need not equal the output matching or be an induced matching. ORS is a parameter in the running-time analysis; the input need not be an ORS graph.
